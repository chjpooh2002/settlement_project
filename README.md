# 미니 멀티셀러 레슨 예약 & 정산 자동화 플랫폼 (Settlement-System)
다중 판매자(Multi-Seller) 환경에서 발생하는 트랜잭션 신뢰성 확보 및 비동기 예약 정산 파이프라인의 핵심 아키텍처를 직접 설계하고 구현한 프로젝트입니다.

---

## 🎯 핵심 아키텍처 및 차별화 포인트

### 1. 도메인 주도 설계(DDD) 전술적 패턴 적용
- 서비스 계층이 엔티티의 필드를 무분별하게 수정하는 '빈약한 도메인 모델'을 지양하고, 엔티티 객체 스스로가 제약 조건을 검증하고 상태를 제어하는 높은 응집도의 도메인 모델을 구축했습니다.
- 외부 의존성을 낮추기 위해 계층형 패키지 구조 대신 도메인(Member, Product, Order, Settlement)별 패키지 구조를 차용했습니다.

### 2. 고정소수점 데이터 무결성 보장 (`BigDecimal`)
- 이커머스 및 정산 도메인 특성상 원 단위까지 정확한 산식이 요구되므로, 부동 소수점 정밀도 누수가 발생하는 `double` 타입을 배제하고 `BigDecimal`을 필수로 도입하여 금융 연산의 신뢰성을 확보했습니다.

### 3. @Scheduled 기반 비동기 정산 배치 파이프라인 (Batch Processing)
- 실시간 결제 시점에 정산 데이터를 동기 방식으로 생성할 경우 발생하는 트랜잭션 지연 및 성능 저하 문제를 분리(Decoupling)했습니다.
- 리소스가 여유로운 새벽 시간대에 결제 완료(`COMPLETED`) 건을 일괄 수집하여 플랫폼 수수료(10%)와 부가세를 자동 가공·적재하는 스케줄링 배치를 아키텍처적으로 분리 최적화했습니다.

### 4. Mockito 기반 초고속 격리 단위 테스트 수립
- Spring Boot와 데이터베이스(RDBMS)를 직접 구동하는 무거운 통합 테스트 대신, `@Mock`과 `ArgumentCaptor`를 활용한 슬라이스 단위 테스트를 수립했습니다.
- 이를 통해 외부 데이터베이스 의존성 없이 단 1~2초 만에 핵심 수수료 연산 로직의 정합성을 보장하는 초고속 피드백 루프를 구축했습니다.

## 🛠️ 사용 기술 및 환경 (Tech Stack)
- **Backend Core**: Java 17, Spring Boot 3.x
- **Data Access**: Spring Data JPA, QueryDSL (동적 검색 및 조인 성능 최적화)
- **Database**: MySQL
- **Test Framework**: JUnit5, Mockito
- **Build Tool**: Gradle

---

## 📊 도메인 모델 관계 (ERD)
- **Member**: USER(구매자)와 SELLER(레슨프로/사업자) 권한 분리 모델링
- **Product**: 다중 판매자 정산의 기준점이 되는 `seller_id` 외래키(FK) 매핑
- **Orders & OrderProduct**: 1회 결제 시 복수의 레슨 상품 주문 처리가 가능하도록 1:N 마스터-상세 구조 분리 및 결제 시점의 '가격 스냅샷(`orderPrice`) 컬럼' 구축을 통한 데이터 왜곡 방지
- **Settlement**: 주문 상세 및 판매자와 유기적 관계를 맺는 정산 예정/완료 데이터 독립 격리 적재 테이블
